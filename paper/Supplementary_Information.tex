Each prospective registration records hashes of the prompts, model checkpoint, protocol,
acquisition code, scoring code, runtime details, and maximum model calls. A run
writes an attempt record before loading the model, then writes one result file
and one integrity record. Scoring checks these hashes before writing one
summary. An adversarial audit found a metadata-linking problem in E29.14c V1
before the model ran; V2 fixed the link without changing the scientific design.

Some sealed registration files contain historical absolute paths. These paths
are inert provenance fields. They are preserved byte-for-byte because changing
them would invalidate the registered SHA-256 hashes. The public replay
manifests use portable repository-relative paths.

\suppnote{Reproducibility release}

The release at
\url{https://github.com/Biodyn-AI/causal-interfaces/releases/tag/v1.0.0}
contains the exact registrations, protocol code, saved per-example outputs,
scientific summaries, integrity manifests, focused tests, figure generator,
and manuscript sources.

All four GPT-2 Medium summaries were recomputed from saved per-example outputs.
They matched exactly on the release platform. To accommodate last-bit CPU
rounding differences across operating systems, the portable gate requires
exact structure, strings, integers, and booleans, and absolute and relative
tolerances of $10^{-12}$ for floating-point values. Fresh model inference and
scoring for E29.14a and E29.14b were also repeated on Python 3.12.15 and macOS
27 rather than the historical Python 3.12.9/macOS 26.3 environment, and matched
exactly. The longer E29.14c and E29.14d model runs were not repeated in that
audit, although their saved outputs pass the strict portable replay.

The cross-model and cross-task GPT-2 Small replication has a separate fixed
record. SHA-256 prefixes for its active prospective registration, saved
outputs, scoring repair, and
final score are, respectively, \texttt{39a5a589678c},
\texttt{2af40febecf9}, \texttt{ed2a268cddad}, and
\texttt{fe8a834c7434}. Its integrity record also hashes the checkpoint,
data-collection code, and scoring code. Its saved-label replay uses the same
strict cross-platform comparison policy.

The portable score replay makes no model calls. Optional fresh-inference
commands download exact GPT-2 checkpoint revisions from Hugging Face and write
to a new output directory. They never overwrite the published evidence. The
repository README and \texttt{docs/REPRODUCIBILITY.md} give step-by-step
commands and expected success fields.

\suppnote{Exact prompts and changed-token positions}

The four sequence-completion templates are:
\begin{enumerate}
  \item \texttt{Replay the sequence: a b c d | a b c}
  \item \texttt{Loop example: a b c d; continue a b c}
  \item \texttt{After a b c d, repeat a b c}
  \item \texttt{Pattern: a b c d. Continue: a b c}
\end{enumerate}

Tokenizer checks require one-token content words, equal recipient and donor
lengths, different targets, and exact position records. The changed-token set
includes the demonstration prefix, demonstrated target, and repeated query.
Shared punctuation, spaces stored in nearby tokens, and fixed template text
remain unchanged, as determined by exact token-identifier equality.

The cross-model and cross-task replication uses four fixed indirect-object templates and
16 unfiltered prompt pairs. Each pair changes exactly three aligned name-token
positions. The complete prompt panel and token records are stored in the
prospective registration and saved labels in the public release.

\suppnote{Why agreement is not only a ceiling effect}

Two patches can appear to agree because both have pushed the output as far as
it can go. Three checks address this concern. First, the 24- and 32-component
sets without the first MLP were selected without looking at their responses and
remain far from the donor output. Second, at 36 components the average distance
from the donor is 0.10032, with one-sided 95\% lower bound 0.08614, while the
one-sided 95\% upper bound on the difference between changed-position and
all-position patches is only 0.00863. Third, each 24--44-component scale uses
many component sets and reports checks by example, prompt template, and
component set. The 47-component point is presented only as a final backup and
position check, not as evidence of varied output behavior.

\suppnote{Transparent repair history}

The E29.14c registration was revised before output creation, attempt
consumption, model loading, or response because its first version did not link
all metadata correctly. The second version changed no scientific condition or
threshold.

The GPT-2 Small replication also has two documented repairs. Registration V1
was superseded before the model ran because a tuple/list JSON round-trip check
failed. After labels were sealed, the original scorer stopped before reading
any scientific value because JSON keys had been serialized alphabetically
rather than in the registered order. A separately hash-sealed, outcome-blind
adapter restored that order and delegated all calculations and
gates to the unchanged scorer. No prompt, condition, threshold, scientific
value, or calculation changed.
